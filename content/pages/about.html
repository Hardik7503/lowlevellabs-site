Why this site exists

Most documentation tells you which function to call. LowLevel Labs explains what that call does underneath: which bus transaction it starts, which cache line it touches, which context it runs in, and what breaks when you get it wrong.

Every article aims for three things: a clear mental model, a diagram that makes the model visible, and code or commands you can try on real hardware or an emulator.

What's covered

  • Embedded firmware: startup code, linker scripts, interrupts, peripherals and bring-up.
  • Linux device drivers: the driver model, Device Tree, character devices, ioctl and locking.
  • C and assembly: the parts of the language that touch hardware, ARM and x86-64 calling conventions.
  • CPU internals: pipelines, caches, coherence, virtual memory and multicore communication.
  • RTOS and VxWorks: scheduling, synchronization, priority inversion and VxWorks architecture.
  • Boot and platform: BIOS, UEFI, partition tables and the path from reset to the kernel.

A note on accuracy

Low-level behaviour depends on the exact core, SoC, kernel version and toolchain. Articles say where behaviour is implementation-defined, and the reference manual for your part always wins. If you spot an error, please get in touch so it can be fixed.
