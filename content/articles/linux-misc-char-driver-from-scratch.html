What we are building

A driver for a virtual device, /dev/llbuf, that stores up to 4 KB. Writing to it replaces the contents; reading returns them. There is no hardware, so you can run it in a VM, but the structure is exactly what a real driver uses: a module, a registered device, a file_operations table, safe copying across the user/kernel boundary, and a lock.

Why a misc device

A classic character driver allocates a major/minor range with alloc_chrdev_region(), initializes a struct cdev, creates a class and calls device_create() so udev makes the /dev node. The misc framework does all of that in one call, using the shared major number 10 and a dynamic minor. For a single device node it is the right default.

The driver

```c // SPDX-License-Identifier: GPL-2.0 #include #include #include #include #include #define LLBUF_SIZE 4096 static char llbuf_data[LLBUF_SIZE]; static size_t llbuf_len; /* bytes currently stored */ static DEFINE_MUTEX(llbuf_lock); /* protects llbuf_data and _len */ static ssize_t llbuf_read(struct file *f, char __user *ubuf, size_t count, loff_t *ppos) { ssize_t ret; if (mutex_lock_interruptible(&llbuf_lock)) return -ERESTARTSYS; /* Copies min(count, len - *ppos) bytes, advances *ppos, returns 0 at EOF. */ ret = simple_read_from_buffer(ubuf, count, ppos, llbuf_data, llbuf_len); mutex_unlock(&llbuf_lock); return ret; } static ssize_t llbuf_write(struct file *f, const char __user *ubuf, size_t count, loff_t *ppos) { if (count > LLBUF_SIZE) return -EFBIG; if (mutex_lock_interruptible(&llbuf_lock)) return -ERESTARTSYS; if (copy_from_user(llbuf_data, ubuf, count)) { mutex_unlock(&llbuf_lock); return -EFAULT; } llbuf_len = count; mutex_unlock(&llbuf_lock); *ppos += count; return count; } static const struct file_operations llbuf_fops = { .owner = THIS_MODULE, .read = llbuf_read, .write = llbuf_write, .llseek = default_llseek, }; static struct miscdevice llbuf_dev = { .minor = MISC_DYNAMIC_MINOR, .name = "llbuf", /* creates /dev/llbuf */ .fops = &llbuf_fops, .mode = 0666, /* demo only: world read/write */ }; static int __init llbuf_init(void) { int ret = misc_register(&llbuf_dev); if (ret) return ret; pr_info("llbuf: registered /dev/%s, minor %d\n", llbuf_dev.name, llbuf_dev.minor); return 0; } static void __exit llbuf_exit(void) { misc_deregister(&llbuf_dev); pr_info("llbuf: unregistered\n"); } module_init(llbuf_init); module_exit(llbuf_exit); MODULE_LICENSE("GPL"); MODULE_AUTHOR("LowLevel Labs"); MODULE_DESCRIPTION("Minimal misc character device example"); ```

Walking through the important lines

The __user pointers

ubuf is an address in the calling process's address space. The kernel must never dereference it directly: it may be unmapped, swapped out or deliberately point into kernel memory. copy_from_user() and copy_to_user() validate the range, handle page faults safely and return the number of bytes they could not copy. Any non-zero result means -EFAULT. The __user annotation lets the sparse checker catch direct dereferences.

The file position

*ppos is the per-open file offset. cat keeps calling read() until it returns 0, so a read that ignores *ppos and always returns data makes cat loop forever, which is the most common first-driver bug. simple_read_from_buffer() handles the offset and end-of-file for you.

The lock

Two processes can call write() at the same time on different CPUs. Without the mutex, one could be copying into llbuf_data while the other updates llbuf_len, and a reader could see a mix of both. A mutex is the right lock here because both paths run in process context and copy_from_user() may sleep on a page fault; a spinlock would be a bug. See Spinlocks vs Mutexes for the rules.

mutex_lock_interruptible() lets a user kill a process that is waiting for the lock. Returning -ERESTARTSYS tells the kernel to restart or abort the system call as appropriate.

Return values

Kernel functions return negative errno values on failure. The C library turns -EFBIG into a return of -1 with errno = EFBIG, so the shell prints "File too large".

Building out of tree

```makefile obj-m := llbuf.o KDIR ?= /lib/modules/$(shell uname -r)/build all: $(MAKE) -C $(KDIR) M=$(PWD) modules clean: $(MAKE) -C $(KDIR) M=$(PWD) clean ```

You need the headers for your running kernel (linux-headers-$(uname -r) on Debian and Ubuntu). For an embedded board, point KDIR at the board's kernel build tree and add ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-. Recipe lines in a Makefile must start with a tab.

Loading and testing

```bash make sudo insmod llbuf.ko sudo dmesg | tail -n 2 # llbuf: registered /dev/llbuf, minor 123 ls -l /dev/llbuf # crw-rw-rw- 1 root root 10, 123 ... echo "hello from user space" > /dev/llbuf cat /dev/llbuf # hello from user space head -c 5000 /dev/zero > /dev/llbuf # -> File too large sudo rmmod llbuf ```
Secure Boot

On a distribution kernel with Secure Boot enabled, insmod may refuse an unsigned module with "Key was rejected by service". Test in a VM without Secure Boot, or sign the module with a key enrolled through MOK.

Debugging when it goes wrong

  • Read dmesg first. An oops prints the faulting function and offset, for example llbuf_write+0x4c/0xb0. Turn that into a source line with scripts/faddr2line llbuf.ko llbuf_write+0x4c.
  • Enable the debugging options on a test kernel: CONFIG_PROVE_LOCKING (lockdep), CONFIG_DEBUG_ATOMIC_SLEEP and CONFIG_KASAN catch most locking and memory bugs the first time they happen instead of the hundredth.
  • Use strace on the user side to see exactly which system calls hit your driver and what they returned.
  • Prefer dev_dbg() and dynamic debug over sprinkling printk: messages can be switched on at runtime through /sys/kernel/debug/dynamic_debug/control.
