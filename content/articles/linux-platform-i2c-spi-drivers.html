The key question: how does the CPU reach the registers?

  • Platform devices are memory-mapped peripherals inside the SoC. Their registers appear in the CPU's address space, so a register read is one instruction taking nanoseconds.
  • I²C and SPI devices are separate chips on a serial bus. The CPU cannot address their registers. It asks the bus controller to send a transaction, which takes microseconds to milliseconds and finishes with an interrupt.

Two layers of drivers

For I²C and SPI, Linux splits the work in two:

  • The controller driver (also called adapter or master driver) operates the SoC's I²C or SPI hardware. It is itself a platform driver, and it registers a bus: i2c-1, spi0.
  • The device driver (also called client or protocol driver) knows the sensor, EEPROM or flash chip. It never touches the controller's registers; it just says "write these bytes to address 0x48".

Because of the split, a temperature sensor driver works on any SoC whose I²C controller has a driver. That reuse is the point of the model.

The same register read, three ways

```c /* Platform: memory-mapped, one instruction */ u32 status = readl(priv->base + STATUS_REG); /* I2C: SMBus "read byte data" = START, addr+W, reg, RESTART, addr+R, data, STOP */ s32 val = i2c_smbus_read_byte_data(client, STATUS_REG); if (val < 0) return val; /* NACK, timeout, bus error ... */ /* SPI: command byte out, one byte back, with chip select held */ u8 cmd = STATUS_REG | 0x80; /* many SPI chips use bit 7 to mean "read" */ u8 val8; int ret = spi_write_then_read(spi, &cmd, 1, &val8, 1); ```

Notice the error handling. A memory-mapped read cannot fail in a way software sees. An I²C or SPI transfer can: the device may not answer, the bus may be stuck, or a timeout may expire. Every serial-bus access needs its return value checked.

regmap: one API for all three

Many drivers use regmap, which hides the bus behind regmap_read(), regmap_write() and regmap_update_bits(), and adds register caching, locking and debugfs dumps. Chips that offer both I²C and SPI interfaces often share one core driver with two thin bus front ends.

```c static const struct regmap_config cfg = { .reg_bits = 8, .val_bits = 8, .max_register = 0x7f }; /* in an I2C probe */ map = devm_regmap_init_i2c(client, &cfg); /* in an SPI probe */ map = devm_regmap_init_spi(spi, &cfg); regmap_update_bits(map, CTRL_REG, CTRL_ENABLE, CTRL_ENABLE); /* same code either way */ ```

The consequence that bites people: sleeping

An I²C or SPI transfer waits for the controller's completion interrupt, so it sleeps. That means you cannot read an I²C sensor from a hard interrupt handler or while holding a spinlock.

Typical case: an I²C GPIO expander or touch controller asserts an interrupt line, and the handler must read a status register over I²C to find out why. The solution is a threaded interrupt: the hard handler does nothing, and the real handler runs in a kernel thread where sleeping is allowed.

```c ret = devm_request_threaded_irq(dev, client->irq, NULL, /* no hard-IRQ handler */ touch_irq_thread, /* runs in a thread, may sleep */ IRQF_ONESHOT, /* keep line masked until thread finishes */ "touch", priv); ```

See Linux Kernel Contexts for the full rules.

Debugging tips per bus

  • Platform: wrong reg base or a disabled clock gives reads of all zeros or all ones, or an external abort. Check the clock and reset first.
  • I²C: i2cdetect -y 1 scans for devices that acknowledge. No answer means wrong address, missing pull-ups, the device unpowered or held in reset. A bus stuck with SDA low needs a recovery sequence (nine clock pulses).
  • SPI: check mode (CPOL/CPHA) and maximum frequency against the datasheet. A logic analyzer on SCK, MOSI, MISO and CS settles most arguments in minutes.
Key takeaway

Platform devices are memory-mapped and accessed directly. I²C and SPI devices sit behind a controller, so their drivers send bus transactions that can fail and can sleep. Controller and device drivers are separate, regmap can hide the difference, and sleeping access means threaded interrupts and no spinlocks around register I/O.
