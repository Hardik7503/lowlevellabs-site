What C needs before it can run

A C program quietly assumes several things are already true when main() starts:

  • There is a stack, and the stack pointer points at it.
  • Initialized globals such as int baud = 115200; hold their initial values. On a microcontroller those values are stored in flash, but the variables live in RAM.
  • Uninitialized globals and statics (.bss) are zero. RAM contents at power-on are undefined.
  • For C++ or __attribute__((constructor)), static constructors have run.

On a desktop the OS loader and the C runtime do this. On bare metal, nobody does it unless your startup code does.

Step 1: the hardware reads the vector table

On reset, a Cortex-M core does not start executing at address 0. It reads two words from the vector table, which is at address 0x0000_0000 by default (many parts alias flash there, and cores with VTOR let software move the table later):

  1. Word 0 is loaded into the main stack pointer (MSP).
  2. Word 1 is the address of the reset handler. The core loads it into PC and starts executing there.

Because the hardware sets up the stack pointer itself, the reset handler can be written in C. That is unusual: most other architectures need at least a few assembly instructions first.

Step 2: the linker script decides where everything lives

The linker script describes the memory map and where each output section goes. The key idea is that .data has two addresses: a load address in flash (LMA), where the initial values are stored in the image, and a run address in RAM (VMA), where the code expects the variables to be.

```ld MEMORY { FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 256K RAM (rwx) : ORIGIN = 0x20000000, LENGTH = 64K } _estack = ORIGIN(RAM) + LENGTH(RAM); /* stack grows down from top of RAM */ SECTIONS { .isr_vector : { KEEP(*(.isr_vector)) } > FLASH .text : { *(.text*) *(.rodata*) } > FLASH _sidata = LOADADDR(.data); /* where initial values sit in flash */ .data : { _sdata = .; *(.data*) _edata = .; } > RAM AT > FLASH /* run in RAM, load from flash */ .bss (NOLOAD) : { _sbss = .; *(.bss*) *(COMMON) _ebss = .; } > RAM } ```

KEEP stops --gc-sections from discarding the vector table: nothing in the program references it, only the hardware does. .bss takes no space in the image at all, because its contents are known to be zero.

Step 3: the reset handler

```c #include extern uint32_t _sidata, _sdata, _edata, _sbss, _ebss, _estack; extern int main(void); extern void SystemInit(void); /* clocks, flash wait states, FPU */ extern void __libc_init_array(void); /* newlib: static constructors */ void Reset_Handler(void) { /* 1. Copy initialized data from flash to RAM. */ uint32_t *src = &_sidata; for (uint32_t *dst = &_sdata; dst < &_edata; ) *dst++ = *src++; /* 2. Zero .bss. */ for (uint32_t *dst = &_sbss; dst < &_ebss; ) *dst++ = 0; /* 3. Clock tree, PLL, flash latency, enable FPU if present. */ SystemInit(); /* 4. C++ constructors and constructor attributes. */ __libc_init_array(); main(); for (;;) { } /* main should never return */ } ```

The linker symbols are declared as uint32_t objects only so we can take their addresses. Their "value" is meaningless; &_sdata is the address the linker assigned. Word-sized copies work because the linker script aligns these sections to 4 bytes (add . = ALIGN(4); around them if your script does not).

Pitfall: SystemInit and .data

Some vendor startup files call SystemInit() before copying .data, so it runs early at the reset clock speed. Any global it reads at that point still holds garbage. If SystemCoreClock is wrong after boot, check the order.

The vector table in C

```c void Default_Handler(void) { for (;;) { } } void NMI_Handler(void) __attribute__((weak, alias("Default_Handler"))); void HardFault_Handler(void) __attribute__((weak, alias("Default_Handler"))); void SysTick_Handler(void) __attribute__((weak, alias("Default_Handler"))); __attribute__((section(".isr_vector"), used)) const void *const vector_table[] = { &_estack, Reset_Handler, NMI_Handler, HardFault_Handler, /* ... MemManage, BusFault, UsageFault, reserved, SVCall, PendSV ... */ [15] = SysTick_Handler, /* [16 + n] = IRQn handlers from the vendor's table */ }; ```

Weak aliases are why you can define void USART1_IRQHandler(void) anywhere in your project and it is automatically used: your strong definition overrides the weak default. Misspell the name and you silently get Default_Handler, which is a common reason an interrupt "hangs the board".

Debugging a board that never reaches main()

  • Check the first two words of the image. arm-none-eabi-objdump -s -j .isr_vector fw.elf. Word 0 should be the top of RAM, word 1 an odd address inside flash.
  • Check the map file. Link with -Wl,-Map=fw.map and confirm .data has a RAM VMA and a flash LMA.
  • Halt at reset. In GDB with OpenOCD or a J-Link: monitor reset halt, then info registers sp pc. If SP or PC are not what the table says, the table is not where the core is looking (boot pins, VTOR, wrong flash offset).
  • A HardFault before main() usually means a stack placed outside RAM, a missing Thumb bit, or SystemInit() touching a peripheral whose clock is not enabled.
Key takeaway

Reset on a Cortex-M is: hardware loads SP and PC from the vector table, then your reset handler copies .data, zeroes .bss, configures clocks, runs constructors and calls main(). The linker script is the contract between those steps. Read it as carefully as the code.
