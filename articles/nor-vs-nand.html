NOR vs. NAND Flash: What's the Difference?

Both keep data without power, and both are called flash. But NOR behaves like slow ROM you can read byte by byte, while NAND behaves like a cheap, dense disk that needs software to manage it. The difference starts with how the cells are wired.

What a flash cell is

A flash cell is a transistor with an extra, electrically isolated floating gate. Pushing electrons onto that gate changes the voltage needed to switch the transistor on. Reading the cell means checking whether it switches on at a given voltage. Because the floating gate is insulated, the electrons stay put for years with no power.

Two rules follow from the physics and shape everything else:

  • Programming can only move bits from 1 to 0.
  • Erasing (resetting bits back to 1) is only possible for a large group of cells at once, called an erase block, and wears the cells out a little each time.

So you can never overwrite a byte in place. To change a 0 back to 1 you must erase the whole block it lives in.

The name comes from the wiring

NOR flash

NOR has an interface like SRAM or ROM (parallel NOR) or a simple serial protocol (SPI or QSPI NOR, the common form today). Any byte can be read directly at its address, and reads are fast and reliable.

That enables eXecute In Place (XIP): the CPU fetches instructions straight from flash without copying them into RAM first. Almost every microcontroller runs its firmware this way, and many SoCs boot from a small SPI NOR chip.

  • Typical sizes: 1 MB to 256 MB.
  • Erase blocks (sectors): commonly 4 KB to 256 KB. Erasing is slow, tens to hundreds of milliseconds.
  • Endurance: around 100,000 erase cycles per block.
  • Bits are effectively always correct, so no error correction is normally needed.

NAND flash

NAND is organized like a disk. Data is read and programmed in pages (typically 2 to 16 KB, plus a small "spare" or out-of-band area per page), and erased in blocks of 64 to several hundred pages.

NAND is not perfect, and software has to manage it:

  • Bad blocks exist from the factory and more appear with use. They are marked in the spare area and must be skipped.
  • Bit errors occur in normal operation, increasingly as cells wear and as more bits are stored per cell (SLC 1 bit, MLC 2, TLC 3, QLC 4). Every page needs ECC (error-correcting codes such as BCH or LDPC).
  • Wear leveling spreads erases evenly so no block dies early. SLC endures roughly 50,000 to 100,000 cycles; TLC and QLC only about 1,000 to 3,000.
  • Read disturb and retention: repeatedly reading a block or leaving it unpowered for a long time slowly corrupts it, so data must be refreshed.

Raw NAND vs managed NAND

Someone has to do the bad-block handling, ECC and wear leveling. There are two options:

  • Raw NAND: the SoC's NAND controller does ECC, and software does the rest. In Linux that means the MTD layer with UBI and a flash filesystem such as UBIFS.
  • Managed NAND: eMMC, SD cards, UFS and SSDs contain NAND plus a controller running a Flash Translation Layer (FTL). The host sees an ordinary block device. This is what most products use today.

A typical embedded Linux board uses both

A small SPI NOR chip holds the bootloader (the Boot ROM can read it simply and reliably), and an eMMC holds the kernel, root filesystem and data. Microcontrollers usually have only NOR, built into the chip, and run code from it directly.

Pitfall: writing flash from firmware

On many microcontrollers you cannot execute code from a flash bank while erasing or programming the same bank: the CPU stalls or faults. Code that updates firmware or stores settings often has to run from RAM, or use a second bank.

Key takeaway

NOR wires cells in parallel: random-access reads, execute in place, reliable, but small and expensive. NAND wires cells in series: dense and cheap, but page-based, with bad blocks, bit errors and wear that software or an FTL must manage. Boot code goes in NOR; bulk storage goes in NAND.
