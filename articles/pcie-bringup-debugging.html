PCIe Bring-Up: A Practical Debugging Checklist

When a PCIe device "doesn't show up", the cause can be anywhere from a missing reference clock to a driver bug. PCIe is built in layers, and debugging goes fastest when you check them in order, bottom up.

PCIe in five minutes

PCI Express connects a CPU to devices such as SSDs, network cards, GPUs and FPGAs. It replaced the old parallel PCI bus with fast serial links, but kept PCI's software model, which is why the same enumeration and drivers still work.

  • A lane is one pair of differential wires in each direction. A link has 1, 2, 4, 8 or 16 lanes (x1 to x16).
  • Each generation raises the per-lane rate: Gen1 2.5 GT/s, Gen2 5, Gen3 8, Gen4 16, Gen5 32 GT/s.
  • The Root Complex sits in the CPU or SoC. Endpoints are the devices. Switches fan one link out to several.
  • Devices are addressed by Bus:Device.Function (BDF), for example 01:00.0.

The layers, bottom up

Bring-up means confirming each layer works before trusting the one above it:

1. Physical layer

Most "PCIe software problems" on a new board are hardware. Check:

  • Power rails to the endpoint are up and stable before reset is released.
  • Reference clock (usually 100 MHz differential) is present on both sides, or each side is configured for its own clock if the design uses separate clocks.
  • PERST# (the reset line) is held low until power and clock are stable, then released. The specification requires at least 100 ms from power-good to PERST# release. Some FPGAs need longer because they load their configuration first.
  • Lane polarity and order: polarity inversion within a pair is corrected automatically, and lane reversal is usually supported, but swapped transmit and receive pairs never work.
  • AC coupling capacitors on the transmit side, correct placement and value.

2. Link training

When reset is released, both ends run the LTSSM (Link Training and Status State Machine). They detect each other's receivers, exchange training sequences to lock bit and symbol alignment, agree on width and speed, and arrive in state L0, which means the link is up. Faster speeds also run equalization to tune the transmitters for the channel.

  • Most root-complex controllers expose the current LTSSM state in a debug register. A link stuck in Detect means the receiver is not seen at all (power, reset, wiring). Stuck in Polling or Configuration usually means signal-integrity or lane-mapping problems.
  • A link that trains at Gen1 but fails at Gen3 or Gen4 points at signal integrity or equalization.
  • Check the negotiated result:
sudo lspci -s 01:00.0 -vv | grep -E 'LnkCap|LnkSta'
#   LnkCap: Port #0, Speed 16GT/s, Width x4 ...     <- what the device supports
#   LnkSta: Speed 8GT/s (downgraded), Width x2 (downgraded)   <- what it actually got

"Downgraded" is a strong hint: a lane is broken, or the channel cannot sustain the higher speed.

3. Enumeration

Every PCIe function has a configuration space (256 bytes for legacy PCI, 4 KB for PCIe). Its first bytes hold the Vendor ID and Device ID. At boot, firmware or the OS performs enumeration: it walks the tree, reads the Vendor ID at each possible BDF, and records what it finds. An empty slot reads as 0xFFFF.

lspci -nn                         # list devices with [vendor:device] IDs
sudo lspci -s 01:00.0 -xxx        # hex dump of configuration space
  • Link up but no device in lspci: the endpoint was not ready when enumeration ran. Common with FPGAs that load late. Rescan with echo 1 | sudo tee /sys/bus/pci/rescan, or delay enumeration.
  • On embedded SoCs, check that the root complex is enabled in the Device Tree and its driver probed: dmesg | grep -i pci.

4. BARs and resources

A device tells the host how much memory it needs through Base Address Registers (BARs) in configuration space. The OS sizes each BAR (by writing all ones and reading back which bits stick), assigns an address range in the CPU's physical address space, and writes the base address back. From then on, CPU reads and writes to that range reach the device's registers.

  • "BAR 0: no space for [mem size 0x10000000]" in dmesg means the root complex's memory window, set in the Device Tree ranges or by firmware, is too small for what the device asks for.
  • In lspci -vv, a Region 0: Memory at ... [disabled] or [virtual] line means the BAR was not enabled. Check the Command register's Memory Space Enable bit.

5. Driver, interrupts and DMA

  • Bus mastering must be enabled (pci_set_master()) before the device can DMA. Forgetting it gives silently zero transfers.
  • Interrupts: PCIe uses MSI/MSI-X, which are memory writes to a special address, not wires. If interrupts never arrive, check that the MSI controller is configured in the platform and that lspci -vv shows MSI: Enable+.
  • IOMMU: with an IOMMU active, the device can only reach memory mapped for it through the DMA API. Using raw physical addresses produces IOMMU faults in dmesg.
  • Errors: AER (Advanced Error Reporting) logs correctable and uncorrectable errors. A steady stream of correctable errors means a marginal link even if it "works".

Performance sanity check

A link's usable bandwidth is lower than its raw rate. Gen3 x4 gives about 3.9 GB/s per direction after encoding; protocol overhead (packet headers, flow control, small payloads) typically takes another 10 to 20 percent. If you measure far below that, check:

  • The negotiated speed and width (LnkSta), not the slot's label.
  • Max Payload Size and Max Read Request Size in DevCtl: small values cap throughput.
  • Whether DMA buffers are small, unaligned, or bounced through a swiotlb buffer because of address limits.
Key takeaway

Check PCIe from the bottom up: power, clock and reset; link training to L0 with the expected speed and width; enumeration; BAR assignment; then the driver's interrupts and DMA. Each layer has its own tools, and a problem at a lower layer always shows up as a confusing symptom higher up.
