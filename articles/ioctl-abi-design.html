Designing a Robust ioctl Interface

read() and write() move bytes. Real devices also need commands: set the sample rate, start a capture, query the firmware version. ioctl is the escape hatch for those, and once user programs depend on it, it's a promise you have to keep.

What ioctl is

ioctl(fd, cmd, arg) sends a numbered command to the driver behind a file descriptor, with one argument that is usually a pointer to a structure. The kernel routes it to the driver's .unlocked_ioctl handler.

Before adding one, ask whether something simpler fits. A single value that tools may want to read or set is often better as a sysfs attribute. Bulk data belongs in read()/write() or mmap(). Many device types already have a standard interface (IIO for sensors, V4L2 for cameras, ALSA for audio, input for buttons) that existing tools understand. Use ioctl for genuinely device-specific commands.

Command numbers carry meaning

The command is a 32-bit number encoded with macros from <linux/ioctl.h>:

/* include/uapi/linux/myadc.h -- shared by kernel and user space */
#include <linux/ioctl.h>
#include <linux/types.h>

#define MYADC_MAGIC  'k'      /* check Documentation/userspace-api/ioctl/ioctl-number.rst */

struct myadc_config {
    __u32 sample_rate_hz;
    __u32 channel_mask;
    __u32 flags;              /* MYADC_FLAG_* ; unknown bits must be zero */
    __u32 reserved;           /* explicit padding, must be zero */
};

struct myadc_info {
    __u32 version;
    __u32 num_channels;
    __u64 max_rate_hz;
};

#define MYADC_GET_INFO   _IOR(MYADC_MAGIC, 0x01, struct myadc_info)
#define MYADC_SET_CONFIG _IOW(MYADC_MAGIC, 0x02, struct myadc_config)
#define MYADC_START      _IO (MYADC_MAGIC, 0x03)

_IOR means user space reads data from the kernel; _IOW means user space writes data to the kernel. It's named from the user's point of view, which is a frequent source of confusion.

Structure layout: the 32/64-bit trap

The structure is part of the ABI. A 32-bit program running on a 64-bit kernel must produce the exact same bytes the kernel expects. Several C types break this:

AvoidWhyUse instead
long, size_t4 bytes on 32-bit, 8 on 64-bit__u32, __u64
Pointers in the structSize differs; also needs compat conversion__u64 holding the address, cast with u64_to_user_ptr()
Implicit padding__u64 alignment differs between i386 (4) and x86-64 (8)Order fields large to small, add explicit reserved fields
enum, boolSize is compiler-defined__u32 with defined constants

If every field is a fixed-width type, naturally aligned with no hidden padding, the same handler can serve 32-bit callers directly: set .compat_ioctl = compat_ptr_ioctl.

The handler

static long myadc_ioctl(struct file *file, unsigned int cmd, unsigned long arg)
{
    struct myadc *adc = file->private_data;
    void __user *uarg = (void __user *)arg;

    switch (cmd) {
    case MYADC_GET_INFO: {
        struct myadc_info info = {           /* zero-initialized: no stack leak */
            .version      = 1,
            .num_channels = adc->nchan,
            .max_rate_hz  = adc->max_rate,
        };
        return copy_to_user(uarg, &info, sizeof(info)) ? -EFAULT : 0;
    }
    case MYADC_SET_CONFIG: {
        struct myadc_config cfg;
        int ret;

        if (copy_from_user(&cfg, uarg, sizeof(cfg)))
            return -EFAULT;
        if (cfg.reserved || (cfg.flags & ~MYADC_FLAG_ALL))
            return -EINVAL;                  /* reject unknown bits: keeps them usable later */
        if (!cfg.sample_rate_hz || cfg.sample_rate_hz > adc->max_rate)
            return -EINVAL;
        if (cfg.channel_mask & ~GENMASK(adc->nchan - 1, 0))
            return -EINVAL;

        mutex_lock(&adc->lock);
        ret = adc->running ? -EBUSY : myadc_apply(adc, &cfg);
        mutex_unlock(&adc->lock);
        return ret;
    }
    case MYADC_START:
        return myadc_start(adc);
    default:
        return -ENOTTY;                      /* the standard "unknown ioctl" error */
    }
}

Security checklist

  • Copy first, then validate the copy. Never read the user's memory twice: another thread can change it between the check and the use (a TOCTOU, "double fetch", bug).
  • Validate every field: ranges, indexes, lengths, flag bits.
  • Zero structures you return (designated initializers or memset), including padding, so you don't leak kernel stack contents.
  • Check permissions for privileged commands with capable(CAP_SYS_ADMIN) or a narrower capability.
  • Lock device state: two threads can call ioctl on the same file at once.

Keeping it stable

Linux's rule is that changes must not break existing user programs. Design for extension from the start:

  • Reject unknown flags and non-zero reserved fields today, so you can give them meaning tomorrow.
  • Never change an existing structure. Add a new command, or use a size-versioned structure where the caller passes its size and the kernel handles older, smaller versions.
  • Put the header under include/uapi/ so it is exported to user space, and don't include kernel-internal headers in it.
  • Add a GET_INFO or version command so user space can discover capabilities instead of guessing.

Using it from user space

int fd = open("/dev/myadc0", O_RDWR);
struct myadc_config cfg = { .sample_rate_hz = 48000, .channel_mask = 0x3 };
if (ioctl(fd, MYADC_SET_CONFIG, &cfg) < 0)
    perror("MYADC_SET_CONFIG");     /* EINVAL, EBUSY, ENOTTY ... */
Key takeaway

Encode commands with _IO/_IOR/_IOW, build argument structures from fixed-width types with explicit padding, copy in once and validate everything, zero what you copy out, return -ENOTTY for unknown commands, and treat the interface as permanent.
