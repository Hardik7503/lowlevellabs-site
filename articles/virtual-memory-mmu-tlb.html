Virtual Memory: MMU Page Walks and the TLB

Every load and store your program issues uses a virtual address. The MMU turns it into a physical one, checks permissions and attributes, and does it fast enough that you rarely notice. Until you write a bootloader, a kernel or a driver.

What translation buys you

  • Isolation. Each process gets its own address space, and the kernel's memory is not accessible from user mode.
  • Flexibility. Contiguous virtual buffers can be backed by scattered physical pages, and pages can be loaded lazily or swapped.
  • Attributes per page. Each mapping says whether memory is executable, writable, cacheable or a device. For embedded work this last point matters most: a peripheral mapped as normal cacheable memory will misbehave.

Splitting a virtual address

With 4 KB pages and 48-bit virtual addresses, both AArch64 and x86-64 use the same shape: a 12-bit offset inside the page, and four 9-bit indexes, one per table level. Each table is one 4 KB page holding 512 eight-byte entries.

The page walk

On a TLB miss, the hardware walks the tables. It starts from a base register: TTBR0_EL1 or TTBR1_EL1 on AArch64 (the low and high halves of the address space, typically user and kernel), and CR3 on x86-64.

The final entry holds the physical page number and the attributes: valid, read/write, user/kernel, execute-never, and memory type. On AArch64 the memory type is an index into MAIR_EL1, where you define types such as "Normal, write-back cacheable" and "Device-nGnRE" for registers.

The TLB

Four extra memory reads per access would be ruinous, so the MMU caches recent translations in the Translation Lookaside Buffer. Typical cores have small, fast L1 TLBs (tens of entries, split for instructions and data) backed by a larger unified L2 TLB with a thousand or more entries. Page-walk caches also keep upper-level entries so most misses do not need all four reads.

TLB reach is entries × page size. A thousand 4 KB entries cover only 4 MB, which is why databases, DPDK and some firmware use huge pages: one 2 MB entry covers what 512 small ones would.

Keeping the TLB honest

The TLB is not coherent with the page tables. If you change a page-table entry in memory, the CPU may keep using the old cached translation. Software must invalidate it explicitly.

// AArch64: change one mapping for virtual address in x0 (kernel, EL1)
    str     x1, [x2]            // write the new descriptor
    dsb     ishst               // make the table write visible to the walker
    lsr     x0, x0, #12
    tlbi    vaae1is, x0         // invalidate this VA, all ASIDs, inner shareable
    dsb     ish                 // wait for the invalidation to complete
    isb                         // resynchronize the pipeline
; x86-64: invalidate one page on this CPU
    mov     [rbx], rax          ; write the new PTE
    invlpg  [rdi]               ; flush the TLB entry for the address in rdi

On a multicore system other CPUs can hold the stale entry too. Arm's inner-shareable tlbi ... is variants broadcast in hardware; x86 kernels send an inter-processor interrupt so each core runs invlpg itself (a "TLB shootdown").

ASIDs and PCIDs

Switching processes would otherwise mean flushing the whole TLB. Instead, each entry is tagged with an address-space identifier (ASID on Arm, PCID on x86), so entries from several processes can coexist and a context switch only changes the current tag.

What this means in practice

Bootloaders and early kernel code

Code that turns the MMU on is running at a physical address when it executes the enabling write, and the very next instruction is fetched through translation. The standard trick is an identity mapping (virtual = physical) of that code, so execution continues seamlessly, followed by a jump to the high kernel address.

Drivers

A Linux driver never dereferences a physical register address. ioremap() creates a kernel virtual mapping with device memory attributes, and DMA buffers come from the DMA API, which knows both the CPU's virtual address and the device's bus address. A physical address from a datasheet in a pointer is a bug on any system with the MMU enabled.

Faults

A translation or permission failure raises a fault with an address register (FAR_EL1 or CR2) and a syndrome (ESR_EL1 or the page-fault error code). Most crashes you debug in kernel space start by decoding those two values.

Key takeaway

The MMU splits a virtual address into table indexes, walks up to four levels, and caches the result in the TLB. Page tables carry memory attributes as well as addresses, and changing them requires explicit TLB invalidation with the right barriers.
