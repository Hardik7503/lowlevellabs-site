Bit Manipulation for Hardware Registers in C

Configuring a peripheral is mostly setting and clearing bits in 32-bit registers. The C is short, but there are about five ways to get it subtly wrong.

9 min read20 Nov 2026

  4. Write-1-to-clear status registers

The four basic operations

Every register operation reduces to these, applied with a mask that has ones in the bit positions you care about:

reg |=  mask;          /* set bits     */
reg &= ~mask;          /* clear bits   */
reg ^=  mask;          /* toggle bits  */
if (reg & mask) { }    /* test bits    */

Build masks from 1u, never 1. 1 << 31 shifts into the sign bit of a signed int, which is undefined behaviour in C before C23, and 1 << 32 is undefined in every version. Use unsigned constants of the register's width.

#define BIT(n)            (1u << (n))
#define GENMASK(h, l)     ((~0u >> (31 - (h))) & (~0u << (l)))   /* bits h..l, 32-bit */

Multi-bit fields

Most configuration lives in fields several bits wide. Writing a field means clearing all of its bits, then OR-ing in the new value shifted into place.

#define CR1_EN          BIT(0)
#define CR1_PSC_SHIFT   4
#define CR1_PSC_MASK    GENMASK(6, 4)

static inline uint32_t field_prep(uint32_t mask, uint32_t val)
{
    return (val << __builtin_ctz(mask)) & mask;      /* GCC/Clang: count trailing zeros */
}
static inline uint32_t field_get(uint32_t mask, uint32_t reg)
{
    return (reg & mask) >> __builtin_ctz(mask);
}

void timer_set_prescaler(uint32_t psc)
{
    uint32_t v = TIM1->CR1;                 /* one read          */
    v &= ~CR1_PSC_MASK;
    v |= field_prep(CR1_PSC_MASK, psc);
    TIM1->CR1 = v;                          /* one write         */
}

Note the local copy: one volatile read, edit in a register, one volatile write. Writing TIM1->CR1 &= ...; TIM1->CR1 |= ...; performs two separate writes, and for a moment the hardware sees the field cleared to zero. For a prescaler that might be harmless; for a clock mux or a GPIO mode it can glitch an output. The Linux kernel provides the same helpers as FIELD_PREP() and FIELD_GET() in <linux/bitfield.h>.

The read-modify-write race

GPIOA->ODR |= BIT(5) looks atomic. It is three instructions: load, OR, store. If an interrupt runs between the load and the store and modifies another bit of the same register, the store writes back the stale value and silently undoes the ISR's change.

Three ways out, best first:

  1. Use hardware set/clear registers. Many peripherals provide them for exactly this reason. STM32 GPIO has BSRR: writing 1 to bit n sets pin n, writing 1 to bit n+16 resets it, and zero bits are ignored. A single write, no read, no race.
  2. Use bit-banding or atomic instructions where available. Cortex-M3/M4 bit-band aliases map each bit of SRAM and peripheral space to its own word; Cortex-M7 and M33 do not have bit-banding.
  3. Disable interrupts around the sequence, saving and restoring the previous state.
GPIOA->BSRR = BIT(5);           /* set PA5, atomically   */
GPIOA->BSRR = BIT(5 + 16);      /* reset PA5, atomically */

uint32_t primask = __get_PRIMASK();   /* CMSIS */
__disable_irq();
GPIOA->ODR ^= BIT(5);
__set_PRIMASK(primask);               /* restore, don't blindly enable */

Write-1-to-clear status registers

Interrupt status registers are often W1C: writing 1 to a bit clears that flag, writing 0 leaves it alone. The intuitive code is wrong:

DMA->ISR |= DMA_ISR_TCIF;    /* WRONG: reads all pending flags, writes them all back as 1s,
                                clearing every pending flag, not just TCIF */
DMA->ISR  = DMA_ISR_TCIF;    /* right: write only the bit you mean to clear */

The |= version can silently discard an error flag that arrived at the same time, which then never gets handled. Always check the register's access type in the reference manual: RW, RO, W1C, W1S, RC (read-to-clear) and WO all appear in real devices.

Why not C bit-fields?

C lets you write struct { uint32_t en:1; uint32_t :3; uint32_t psc:3; } cr1;, which looks like a perfect register description. Avoid it for hardware:

  • The order in which bit-fields are allocated within a unit, and whether a field may straddle units, is implementation-defined. Portability across compilers and endianness is not guaranteed.
  • Every assignment to a field is a hidden read-modify-write, sometimes of a different access width than the register supports. Some peripherals fault on byte access to 32-bit registers.
  • Updating two fields becomes two separate writes, with an intermediate state visible to the hardware.

Explicit masks and shifts produce exactly the accesses you write. That predictability is worth the extra characters.

A few useful idioms

x & (x - 1)          /* clear the lowest set bit                      */
x & -x               /* isolate the lowest set bit (x unsigned)        */
(x & (x - 1)) == 0   /* true if x is a power of two (or zero)          */
__builtin_ctz(x)     /* index of lowest set bit; undefined for x == 0  */
__builtin_popcount(x)/* number of set bits                             */
(x + 3u) & ~3u       /* round up to a multiple of 4                    */
Key takeaway

Use unsigned masks, update fields with one read and one write, prefer set/clear registers over read-modify-write, write exactly the bits you mean to W1C registers, and keep C bit-fields away from hardware.
